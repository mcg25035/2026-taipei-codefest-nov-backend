# 現況與風險

截至 2026-11-07，commit `20b1a6a` 之後。

## 已完成

- 規格內的 47 支 API 和 Socket.IO 訊號，79 個測試通過。
- 線上環境已透過公開網域驗證：問答、媒體、Socket.IO、SSE、自動分類、`/resolve`。
- FCM 的認證和發送路徑已用假 token 驗證，且已有一台 Android 註冊 token。

## 還沒驗證

- **真手機收到推播：** 交接時仍在等前端回報。
- **前端完整串接：** 後端無法單獨確認。
- **多人同時使用：** 沒有做過壓力測試。

## 上線前必須處理

這些在 Demo 可以接受，正式上線不行。

| 風險 | 影響 | 建議 |
|---|---|---|
| **任何人都能冒用身分，包含管理員** | `POST /sessions` 相信前端傳的使用者 ID，而城市通的 `userinfo` 沒有簽章。知道管理員的 ID 就能取得管理員權限，看到所有內容和稽核紀錄 | 由城市通提供可驗證的 token，改 `routes/account.js` |
| **現場協助沒有安全機制** | 發問者可能是獨居長者，接案者身分未經驗證，也沒有緊急求助 | 上線前補身分驗證和求助流程，否則先關閉現場協助 |
| **媒體檔沒有權限檢查** | 知道網址就能下載；問答本來就公開，但撤回後才會刪除 | 依實際需求決定是否加簽章 |
| **沒有審核後台** | 無法處理不當內容或詐騙回答。依產品決策由營運方負責，但目前沒有工具 | 和營運方確認需求 |
| **CORS 全開** | `CORS_ORIGIN` 預設 `*` | 改成前端網域 |
| **金鑰曾出現在 AI 對話紀錄** | Firebase 金鑰的內容曾被讀進開發對話 | 比賽結束後撤銷並換新 |

## 營運上的限制

| 項目 | 狀況 |
|---|---|
| 可用性 | 跑在單一開發機，電腦關機就停，沒有自動重啟 |
| 備份 | 沒有自動備份 |
| 資料庫變更 | 沒有遷移機制 |
| 頻率限制 | 存在記憶體，重啟歸零，也不適用多程序 |
| Session | 過期的 session 沒有定期清除 |
| 上傳速度 | 曾量到 15 MB 要 69 秒 |
| 測試資料 | 線上資料庫有 `e2e` 開頭的測試帳號，正式 Demo 前可清空 |

## 分類器

| 指標 | 結果 |
|---|---|
| 強制猜一類的準確率 | 86.7%（105 句） |
| 自動分類的比例 | 81% |
| 自動分類的精確度 | 95.3% |
| TownPass 真實問答 | 10 筆猜對 8 筆 |

**前三項偏樂觀**，因為訓練句和測試句都由 Claude 生成，風格相近。引用時要說明是合成資料的結果。要知道真實準確率，得用真人寫的句子重測。

已知弱點：

- **詐騙會漏判：** 例如「叫我拍身分證給他才可以領補助」被分到行政程序。這類分錯的代價最高。
- **分錯改不了：** 依目前規則，志工只能改未分類的問題，自動分錯時只有發問者能改。
- **外語準確率低：** 英文和其他外語的訓練句很少。
- **只看文字：** 只有圖片或語音的問題一律未分類。

## 尚未實作

- `area.district` 一律是 `null`。
- 語音和影片不會重新編碼，檔內的中繼資料（可能含 GPS）會保留；影片畫面也無法遮蔽個資，只能整段移除。
- 影片長度由前端回報，後端不驗證；影片也沒有縮圖。
- 可信度評分沒有防止集體灌倒讚，低分帳號的投票權重也沒有調降。
- 沒有「有新問題待分類」的主動通知，志工要自己開列表。

## 建議的下一步

1. 確認真手機能收到推播，並走完發問到採納的完整流程。
2. Demo 前清空 `backend/data/`，並備好示範帳號和資料。
3. 用真人句子重測分類器，並替詐騙類加關鍵字規則。
4. 賽後撤銷金鑰；要繼續發展的話，先處理上面「上線前必須處理」的項目。
