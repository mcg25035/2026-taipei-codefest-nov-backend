# 看不懂互助論壇：後端 API 規格

介面的欄位定義以 [`openapi.yaml`](./openapi.yaml) 為準；這份文件說明產品決策和 OpenAPI 表達不了的規則。

## 為什麼做

題目是 2026 城市通黑客松的「看不懂」（理解限制）。規則不能用外部 LLM，手機端模型又難以回答各種問題，所以改由**人幫人**：

- **發問者**：長者、外籍人士等數位弱勢者，操作要和 LINE 一樣簡單。
- **解決者**：熱心的數位原生世代，透過論壇回答並獲得成就感。
- **差異點**：直接在城市通裡發問，並自動帶入使用者卡住的頁面；也能處理公文、合約、疑似詐騙和地圖等日常問題。

## 已確認的決策

| 主題 | 決策 |
|---|---|
| 公開範圍 | 問答全公開，不提供私訊；營運與審核由主辦單位負責 |
| 個資遮蔽 | 上傳前由手機端 OCR 和小模型遮蔽；上傳後可由任何人標記，發問者決定 accept 或 deny |
| 協助方式 | 線上或到現場，Geo 用於配對附近的人 |
| 任務板 | 問題列表的遊戲化呈現，不是另一套系統 |
| 發問內容 | 文字、照片、語音、短影片；城市通內的頁面情境自動帶入 |
| 分類 | 發問者可不選分類，由伺服器的分類器判斷；信心低於 70% 時為 `uncategorized`，由志工分類。志工只能改未分類的問題 |
| 身份 | `user`、`admin`、`bot`，回傳在 `author.role`；Bot 權限和一般使用者相同，只是讓前端標示 |
| 管理員 | 可刪改內容、決定個資標記、停權；操作都留稽核紀錄並保留原內容。可依頁面統計問題數 |
| 自訂標籤 | 和 8 個分類並存，最多 5 個；可模糊搜尋。發問者可增刪，其他人只能新增 |
| 語言 | 記錄語言供篩選，不做自動翻譯 |
| 獎勵 | 積分與徽章，可分享；實質獎勵由營運方決定 |
| 讚與倒讚 | 所有登入者都能投票；倒讚數學 YouTube 不公開，避免情緒性倒讚，API 不回傳，只在後端用於排序和可信度評分 |
| 位置分享 | 三個等級：完全關閉、模糊位置、具體位置 |
| 即時更新 | 資料全走 REST；Socket.IO 只通知前端重抓，個人通知走 SSE |
| 平台 | 只做 Android，不做 iOS 和 APNs |
| 通知管道 | App 在背景或關閉時用 FCM 推播；App 開啟中用 SSE；heartbeat 補抓 |

### 暫定預設值

這些是為了完成規格先訂的值，團隊可以修改：

- 待決定的個資標記：內容持續隱藏，不會逾時自動公開。
- 公開位置：對齊約 500 公尺的網格，距離也由網格點計算。不用隨機偏移，因為重複查詢後取平均就能還原位置。
- 積分：回答被採納 +10，現場任務完成 +30。
- 接現場任務：距離 3 公里內。
- 附近通知：預設半徑 1 公里，每題最多通知最近的 20 人，每人每 10 分鐘最多 1 則；只通知 15 分鐘內回報過位置的人。

## 可信度評分

後端替每位使用者計算可信度評分，用來限制來亂的帳號。評分不會回傳給任何前端，也和可公開、可分享的積分分開。

- **暫定公式：** 回答被採納 +5、現場任務完成 +10、收到正讚 +1、收到倒讚 -2。
- **低於 -10 時：** 回答排序下降、不再收到附近通知、不能接現場任務（回傳 `ASSIST_NOT_ALLOWED`）。
- **未涵蓋：** 目前沒有防止多人集體灌倒讚，低評分帳號的投票權重也沒有調降。

## 位置分享等級

使用者在 `PATCH /me` 設定預設值，發問時可用 `location_sharing` 針對單一問題覆蓋。

| 等級 | 發問者 | 解決者 | 後端保存 |
|---|---|---|---|
| `off` 完全關閉 | 問題沒有位置，不進附近列表，不發附近通知，不能用現場協助 | 收不到附近通知，不能接現場任務 | 不保存 |
| `approximate` 模糊位置（預設） | 公開頁與通知只有約 500 公尺的位置；現場問題有人接案後，精確位置只給接案者 | 用網格點配對附近問題 | 網格點；現場問題另存精確位置，問題解決或撤回時清除 |
| `exact` 具體位置 | 公開頁仍是模糊位置；附近通知與接案者可取得精確座標 | 用精確位置配對 | 保存最新一筆 |

## 系統架構

```text
Vue WebView ──REST / Socket.IO / SSE──┐
                                      ├── 反向代理（自行處理）── Express API ── SQLite、媒體檔
Flutter App ──heartbeat───────────────┘                               │
                                                                 FCM HTTP v1
城市通 App <──────────────────── FCM <────────────────────────────────┘
```

後端用 Express + SQLite，範圍維持單一服務，只提供 HTTP；HTTPS 與反向代理由部署方自行處理。Socket.IO 走同一個 Express 服務；SSE 路由要關閉反向代理緩衝。

## 身分

1. 前端透過 `flutterObject` 取得 `userinfo`。
2. 只把 `id` 傳給 `POST /sessions` 換取 token，**不要傳姓名、身分證字號或電話**。
3. 公開頁面只顯示暱稱。

> **Demo 限制：** `userinfo` 沒有簽章，任何人都能冒用別人的 ID。上線前必須由城市通提供可驗證的 token，屆時只需修改 `POST /sessions`。

## 狀態流程

### 問題

```text
open ──接案──> in_progress ──發問者確認完成──> resolved
  ^                │
  └──── 取消 ──────┘
open ──採納回答或發問者標記已解決──> resolved
```

- `answer_count` 表示是否有人回答，不另設狀態。
- 已解決和回答是分開的：發問者可用 `POST /questions/{id}/resolve` 直接標記，不需要留言或採納，也不會發積分。
- 標記已解決後，仍可回答、按讚和採納。
- 撤回後的問題一律回傳 404。
- 有進行中的現場協助時不能採納回答，回傳 `ASSIST_ACTIVE`。

### 現場協助

```text
claimed ──接案者抵達──> arrived ──發問者確認──> completed
   └───────任一方取消───────┴──> cancelled
```

- 完成由**發問者**確認，積分才會入帳；接案者忘了回報抵達時，發問者一樣能確認。
- `off` 以外的等級都能申請現場協助。
- 精確位置透過 `GET /questions/{id}/assist` 提供給接案者；只有 `exact` 等級會另外放進附近通知。公開列表與詳情都不會出現。
- 取消時接案者立即失去權限；問題解決或撤回時，後端刪除精確座標。

> **待補風險：** 目前沒有現場任務專用的安全機制，例如身分驗證或緊急求助。Demo 可用，正式上線前必須補上，尤其發問者可能是獨居長者。

### 個資標記

```text
建立標記 ──> pending（內容對他人隱藏）──accept──> accepted（不可逆遮蔽）
                                     └─deny───> denied（恢復顯示）
```

- 回答內的個資也由**問題的發問者**決定。
- 發問者看不到是誰標記的。
- 發問者自己標記時直接生效。
- 待決定的媒體，公開網址回傳 404；發問者透過短效的 `preview_url` 查看。
- 圖片遮蔽時產生新檔案與新 ID，舊網址立刻失效，原檔刪除。
- 文字逐字換成 `█`，字數不變，其他待決定標記的位置才不會跑掉。
- 內容待確認時，通知也不會帶問題標題，已發出的通知也會改成通用文字。

> **已知濫用風險：** 任何人都能透過標記暫時隱藏內容。規格只限制單人的標記頻率（每小時 10 次），其他處理交由營運方。

## 通知

| 情況 | 管道 |
|---|---|
| App 在背景或關閉 | FCM 推播，由系統顯示；點擊後城市通開啟 `data.url` |
| App 開啟中 | FCM 推播由城市通顯示成本機通知；頁面用 `GET /notifications/stream`（SSE）即時更新畫面 |
| 推播失敗或未啟用時的備援 | 定時呼叫 `POST /me/heartbeat` 取回未送達的通知 |

每則通知都會推播到使用者所有已註冊的裝置，規則參考城市通的 FCM 規格：

1. 每次載入頁面或登入後，網頁呼叫城市通的 `push_token`，再用 `PUT /push-tokens/{token}` 上傳。token 會變，App 也不會主動通知網頁，所以每次都要上傳；`push_token` 回傳 `null` 時跳過。
2. 使用者由登入 token 判斷，不接受前端傳來的使用者 ID，避免把自己的裝置綁到別人帳號。
3. 推播的 `notification` 帶通知的 `title` 和 `body`；`data` 的值都是字串：`notification_id`、`type`，有問題時另帶 `question_id` 和 `url`。`url` 預設是 `https://tp2026.ydtw.net/?question={question_id}`，前端要在載入時讀取 `question` 參數並直接開啟該問題；可用 `PUSH_QUESTION_URL` 修改。
4. 推播內容會出現在鎖定畫面，所以和 SSE 一樣只放固定文字和問題標題；標題待個資確認時改用通用文字。

**避免重複通知：** 推播已經會顯示通知，網頁收到 SSE 或 heartbeat 的通知時只更新畫面，不要再呼叫 `notify`。

城市通的 `notify` 會比對「已訂閱」和「已取消訂閱」字樣來改動訂閱清單，通知文字要避開這些開頭。

## 即時更新

所有資料都走 REST。Socket.IO 只發「有更新」的訊號，前端收到後重新呼叫 REST；通知則走 SSE。

```text
寫入 REST → 後端更新資料 → Socket.IO 發訊號 → 前端呼叫 REST 抓新資料
```

訊號只帶 ID，不帶內容，所以不會外流個資或精確位置；權限檢查也都集中在 REST。

### Socket.IO

連線時帶 token：`io(url, { auth: { token } })`。驗證失敗會拒絕連線。個人房間在連線時自動加入。

前端發送：

| 事件 | `data` | 時機 |
|---|---|---|
| `feed:subscribe`、`feed:unsubscribe` | 無 | 進入或離開論壇、任務板 |
| `question:subscribe`、`question:unsubscribe` | `{ question_id }` | 進入或離開問題頁 |

後端發送：

| 事件 | 接收者 | `data` | 前端要重抓 |
|---|---|---|---|
| `feed.changed` | 訂閱論壇的人 | 無 | `GET /questions`（沿用目前的篩選條件） |
| `question.changed` | 訂閱該問題的人 | `{ question_id }` | `GET /questions/{id}`；若回傳 404，表示已撤回 |
| `answers.changed` | 訂閱該問題的人 | `{ question_id }` | `GET /questions/{id}/answers` |
| `assist.changed` | 發問者、接案者 | `{ question_id }` | `GET /questions/{id}/assist` |
| `pii_reports.changed` | 發問者 | 無 | `GET /me/pii-reports` |

前端規則：

- 同類訊號要合併，例如 500 毫秒內只抓一次，避免短時間大量請求。
- 重新連線後要重新訂閱，並把目前畫面的資料抓一次，因為離線期間的訊號不會補發。
- 附近列表也用 `feed.changed`，由前端帶自己的座標重抓；訊號本身不含位置。

### SSE

`GET /notifications/stream` 只傳個人通知，事件內容是 `Notification`：

```text
event: notification.created
data: {"id":"n_1","type":"new_answer","title":"有人回答了你的問題", ... }
```

斷線後用 `GET /notifications` 補抓。

## 情境帶入

各功能的「我看不懂」按鈕帶入以下資料：

```json
{
  "service_id": "fee-payment",
  "service_name": "繳費服務",
  "page_route": "/fee-payment/detail/:id",
  "page_title": "停車費查詢"
}
```

這些內容會公開。`page_route` 要用路由樣板，不要放實際的 ID 或 query string；`extra` 也不能放個資。

## 錯誤代碼

| HTTP | `code` | 說明 |
|---|---|---|
| 400 | `VALIDATION_ERROR` | 欄位錯誤，細節在 `details` |
| 401 | `UNAUTHORIZED` | token 缺少或失效 |
| 403 | `FORBIDDEN` | 沒有權限 |
| 403 | `ACCOUNT_BANNED` | 帳號已被停權 |
| 403 | `TOO_FAR` | 超出接案距離 |
| 403 | `LOCATION_SHARING_OFF` | 位置分享已關閉，不能接現場任務 |
| 403 | `ASSIST_NOT_ALLOWED` | 目前不能接現場任務，不透露可信度評分 |
| 403 | `SELF_ACTION_NOT_ALLOWED` | 採納、投票或接案的對象是自己 |
| 404 | `NOT_FOUND` | 不存在或已撤回 |
| 409 | `ALREADY_ACCEPTED` | 問題已有採納的回答 |
| 409 | `ANSWER_ACCEPTED` | 已採納的回答不能刪除 |
| 409 | `ASSIST_ACTIVE` | 有進行中的現場協助 |
| 409 | `ASSIST_ALREADY_CLAIMED` | 任務已被接走 |
| 409 | `INVALID_STATE` | 目前狀態不允許此操作 |
| 413 | `FILE_TOO_LARGE` | 檔案過大 |
| 415 | `UNSUPPORTED_MEDIA_TYPE` | 檔案格式不支援 |
| 429 | `RATE_LIMITED` | 請求過於頻繁 |
